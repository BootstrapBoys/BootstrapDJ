# i18n operations

The bot uses i18next with JSON catalogs under `locales/<locale>/`. English
(`en-US`) is the fallback and the required source of truth.

## Catalogs and namespaces

- `common` — shared words and labels
- `commands` — command metadata and command responses
- `events` — event and setup copy
- `buttons` — control labels and feedback
- `errors` — shared refusals and failures
- `dashboard` — dashboard labels and help text
- `longtail` — migrated command/event/dashboard copy, setup controls, playlists, settings and playback-limit messages awaiting native review

Command metadata is generated with:

```sh
npm run build
node tooling/i18n-extract-commands.mjs
```

The runtime overlays catalog metadata in `src/lib/commandMetadata.ts`.
Every shipped locale must contain the same key set.

## Validation

```sh
npm run i18n:validate
```

The validator checks JSON syntax, required namespaces, missing and extra keys,
`{{placeholder}}` parity, and Discord's 100-character command/option description
limit. CI runs it before lint and build.

## Language selection

`/language language:<code>` and `language set <code>` persist the guild
`language` setting; `/language reset` writes the process default. Prefix and
slash command entry points resolve the setting before `command.run`. Slash
metadata uses Discord localizations, not the guild setting, because command
registration is application-global.

## Dashboard

The dashboard exposes the same `language` setting and localizes its settings
labels/help, player/queue/filter controls, status text, statistics, playlist
detail, login/footer chrome, PWA install copy, and duration units. Do not
duplicate catalog text into the browser template without also adding it here.

## Shipped locales

- Source: `en-US` (canonical); `en-GB` is the British-English source variant.
- AI-translated initial set: `es-ES`, `pt-BR`, `fr`, `de`, `ru`, `ja`, `ko`,
  `zh-CN`, `zh-TW`, `it`, `tr`, `pl`, `nl`, `id`.
- Every AI-generated catalog file contains a top-level `_meta.note`:
  `**AI Translated, awaiting native translation**`; `en-US` remains the source
  catalog and is not marked as AI-translated.
- Language pickers use native names (`Español (España)`, `日本語`, `简体中文`,
  `繁體中文`) rather than translating the fallback language name.
- AI catalogs ship as community drafts. Native corrections are accepted through
  GitHub issues/PRs; this is not an in-house review gate. Keep the `_meta.note`
  until a native contributor has reviewed that locale.

## Import policy

Only the 16 locales above are shipped initially. Upstream's 32 locale folders are
not copied wholesale: our command surface differs. Add or correct a locale by
translating all seven namespace files (`common`, `commands`, `events`, `buttons`,
`errors`, `dashboard`, `longtail`) with the same key/placeholder structure, add
the `_meta.note` for AI drafts, run the validator, and test the language switch
before enabling it.

## Deliberate non-goals

Bun, Drizzle, PostgreSQL/PGlite, Docker, Replit/Nix, and the upstream docs site
remain out of scope. This branch stays on Node 24, Prisma/SQLite, and the
host-specific deployment in `docs/`.

## Community native translations

AI-generated catalogs are shipped deliberately as drafts. Native speakers can
submit a GitHub issue or PR for any locale; no local reviewer is required before
merging a correction. Use `.github/ISSUE_TEMPLATE/translation.yml` for a report,
or edit only the relevant `locales/<language>/` files in a PR.

Preserve keys, `{{placeholders}}`, markdown, backticks, URLs and newlines. A
native contributor may remove that locale's `_meta.note` once the catalog has
been reviewed; otherwise leave it in place as provenance. Run
`npm run i18n:validate` before opening the PR.
